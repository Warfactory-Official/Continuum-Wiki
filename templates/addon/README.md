# {{modName}}

An addon mod for [NTM - Continuum](https://github.com/Warfactory-Official/NTM-Continuum), generated by the
[Continuum Wiki](https://warfactory-official.github.io/Continuum-Wiki/addons/overview/) template generator.

It builds for these nodes (Minecraft version and loader): {{nodeList}}. Golem Core and NTM - Continuum come
from their GitHub releases and GemRender from CurseForge through [CurseMaven](https://www.cursemaven.com/), so no other
checkout is needed.

## Building

You need a JDK to start Gradle (any of 17, 21 or 25). Gradle downloads the Java each node needs (26.1 on 25, 1.21.1 on
21, 1.20.1 on 17).

```bash
./gradlew :{{activeNode}}:dejsonVerify   # every declared texture exists
./gradlew :{{activeNode}}:runClient      # start a dev client
./gradlew chiseledBuild                  # build every node
```

Jars land in `versions/<node>/build/libs/`; the copies without GameTests, for uploading, in `versions/<node>/build/release/`.

The source tree is written once, against the newest node's API. Stonecutter rewrites `src/` in place for the active
node (`{{activeNode}}`), so only one node compiles at a time. `chiseledBuild` switches between them; run
`./gradlew "Reset active project"` before you commit.

Put a version difference in Golem Core, not behind a `//? if` guard here. Loader guards (`//? if neoforge`) belong only
in the `platform` packages.

## Testing in game

Golem Core's harness starts dev clients, drives them from scenarios in `harness/scenarios` and writes screenshots and a
report to `harness/out/`. It needs Java 21+ and, on Windows, Git Bash:

```bash
./harness/harness up --nodes {{activeNode}}
./harness/harness run ExampleBlock.java
./harness/harness down
```

It downloads its CLI from the Golem Core release named by `deps.golemcore`. The build already runs on that release's
`-dev` jars, the regular jars plus the harness listener, which stays idle in a normal run. See
[Testing](https://warfactory-official.github.io/Continuum-Wiki/addons/testing/).

## Updating Golem Core and NTM - Continuum

`gradle.properties` names the release versions:

- `deps.golemcore`: a release of https://github.com/Warfactory-Official/Golem-Core/releases
- `deps.hbm`: a release of https://github.com/Warfactory-Official/NTM-Continuum/releases

When you move to a newer Golem Core, also raise `deps.golemcore_floor` and `deps.hbm_floor` and copy the matching
`gradle/mod/*.gradle.kts` scripts from that Golem Core release into `gradle/golem/`.

Each `versions/<node>/gradle.properties` names GemRender's CurseForge file id, `deps.gemrender`: a file of
https://www.curseforge.com/minecraft/mc-mods/gemrender/files/all for that node's Minecraft version and loader (the number
at the end of the file's page URL).

The dev client run also loads Sodium (`deps.sodium_neoforge` / `deps.sodium_fabric`, plus Indium on 1.20.1 Fabric) or,
on Forge 1.20.1, Embeddium (`deps.embeddium`), from the Modrinth Maven. They are never part of your mod's jar.
`-Psodium.run=false` launches on vanilla's renderer.
