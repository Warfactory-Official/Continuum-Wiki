This page lists every file an addon mod project needs before it has any content. The build is NTM: Space's
([NTM-Continuum-Space](https://github.com/Warfactory-Official/NTM-Continuum-Space)), trimmed, with Golem Core and
NTM - Continuum taken from their GitHub releases and GemRender from CurseForge through
[CurseMaven](https://www.cursemaven.com/). The project builds
on its own: no other checkout is needed. When the files are in place, continue with
[Your first addon mod](../first-addon/).

:::tip[Skip the setup]
The [template generator](../../getting-started/template-generator/) downloads a project with every file on this page,
named and set up for the targets you pick, with the newest releases already filled in.
:::

## Directory layout

```text
my-addon/
  settings.gradle.kts
  stonecutter.gradle.kts
  gradle.properties
  build.neoforge.gradle.kts
  build.fabric.gradle.kts
  build.forge.gradle.kts
  gradlew, gradlew.bat, gradle/wrapper/     copied from NTM: Space
  gradle/
    dejson-classes.txt
    dejson-authored.txt
    golem/            Golem Core's shared build scripts
  harness.json        the harness's nodes and paths
  harness/            harness CLI wrappers; scenarios/ holds your scenarios
  versions/
    26.1-neoforge/gradle.properties
    26.1-fabric/gradle.properties
    1.21.1-neoforge/gradle.properties
    1.21.1-fabric/gradle.properties
    1.20.1-forge/gradle.properties
    1.20.1-fabric/gradle.properties
  src/
    main/java/        one source tree for every node
    main/resources/   one resource tree for every node
    recipes/java/     data written in Java, not shipped (optional)
```

`gradle/golem/` holds Golem Core's shared build scripts (see [The shared build scripts](#the-shared-build-scripts)). Copy
them from `gradle/mod/` of [Golem Core](https://github.com/Warfactory-Official/Golem-Core) at the tag of the release you
build against (<code>v{golemcore.version}</code>), so the scripts match the jar.

## settings.gradle.kts

Stonecutter declares the six nodes. Leave out a `match` line, or a loader in one, to drop a node.

```kotlin title="settings.gradle.kts"
pluginManagement {
    repositories {
        mavenCentral()
        gradlePluginPortal()
        maven("https://maven.fabricmc.net/") { name = "Fabric" }
        maven("https://maven.neoforged.net/releases/") { name = "NeoForged" }
        maven("https://maven.kikugie.dev/releases") { name = "KikuGie" }
        maven("https://maven.kikugie.dev/snapshots") { name = "KikuGie Snapshots" }
    }
}

plugins {
    id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"
    id("dev.kikugie.stonecutter") version "0.9.8"
    id("dev.kikugie.loom-back-compat") version "0.4.2"
}

stonecutter {
    create(rootProject) {
        fun match(version: String, vararg loaders: String) = loaders.forEach {
            version("$version-$it", version).buildscript = "build.$it.gradle.kts"
        }
        match("26.1", "fabric", "neoforge")
        match("1.21.1", "fabric", "neoforge")
        match("1.20.1", "fabric", "forge")
        vcsVersion = "26.1-neoforge"
    }
}

rootProject.name = "myaddon"
```

`loom-back-compat` picks the right Fabric Loom variant per node (obfuscated below 26.1). `vcsVersion` must be a node you
build; the source tree is committed in that node's state.

:::note[Changing Golem Core or HBM at the same time]
NTM: Space builds against local checkouts of Golem Core and NTM - Continuum instead, as Gradle composite builds
(`includeBuild("../Golem-Core")` with a dependency substitution per node, in its
[settings.gradle.kts](https://github.com/Warfactory-Official/NTM-Continuum-Space/blob/main/settings.gradle.kts)). Do the
same only when you change those projects together with your addon; otherwise the released jars are simpler.
:::

## stonecutter.gradle.kts

This file holds the loader constants and the version replacements. Copy NTM: Space's whole file: its `replacements`
block is the same set as HBM's, so your code reads like HBM's on every node. For example `Identifier.fromNamespaceAndPath(`
becomes `dev.golem.core.Ids.of(`, and `Identifier` becomes `ResourceLocation` below 1.21.11.

```kotlin title="stonecutter.gradle.kts (start)"
plugins {
    id("dev.kikugie.stonecutter")
}

stonecutter active "26.1-neoforge" /* [SC] DO NOT EDIT */

tasks.register("chiseledBuild") {
    group = "build"
    dependsOn(stonecutter.tasks.named("build"))
}

tasks.register("publishAllMods") {
    group = "publishing"
    dependsOn(stonecutter.tasks.named("publishMods"))
}

stonecutter parameters {
    val loader = node.metadata.project.substringAfterLast('-')
    constants["fabric"] = loader == "fabric"
    constants["neoforge"] = loader == "neoforge"
    constants["forge"] = loader == "forge"
    constants["forgelike"] = loader == "neoforge" || loader == "forge"
    swaps["mc_version"] = "\"${node.metadata.version}\";"
    constants["jei"] = !(node.project.findProperty("deps.jei") as String?).isNullOrBlank()
    constants["kubejs"] = !(node.project.findProperty("deps.kubejs") as String?).isNullOrBlank()
    replacements {
        // copy NTM: Space's list unchanged
    }
}
```

Use loader guards (`//? if fabric {`) only for loader glue under your `platform` package. A difference between Minecraft
versions belongs in Golem Core, not in your addon mod.

golem.build.legacyAssets.modelNamespace=hbm

## versions/&lt;node&gt;/gradle.properties

Each node's file holds that node's dependency versions and GemRender's CurseForge file. Keep the versions equal to HBM's file for the same node, at the release you build against
([versions/](https://github.com/Warfactory-Official/NTM-Continuum/tree/main/versions)), since the addon mod runs on that HBM
node. The values for NTM - Continuum {hbm.version}, the newest release when this page was built:

<NodeVersions />

`deps.gemrender` is a CurseForge file id: the number at the end of a file's page on
[GemRender](https://www.curseforge.com/minecraft/mc-mods/gemrender/files/all). Pick the file for the node's Minecraft
version and loader; the ids above are GemRender {gemrender.version}. Golem Core and NTM - Continuum are one version each,
`deps.golemcore` and `deps.hbm` in the root `gradle.properties`, naming a release of
[Golem Core](https://github.com/Warfactory-Official/Golem-Core/releases) and
[NTM - Continuum](https://github.com/Warfactory-Official/NTM-Continuum/releases). When you move to a newer release, also
raise `deps.golemcore_floor` and `deps.hbm_floor`, and copy that Golem Core release's scripts into `gradle/golem/`.

Each node also names its dev Sodium: `deps.sodium_neoforge` or `deps.sodium_fabric` (Sodium from Modrinth), and on
1.20.1 Forge `deps.embeddium` (Embeddium, the Forge port; Sodium has no Forge build). 1.20.1 Fabric adds
<code>deps.indium={prop('1.20.1-fabric', 'deps.indium')}</code>: Sodium 0.5 skips Fabric's renderer API without it, which blanks connected textures
and custom models.

1.20.1 Fabric also sets <code>deps.lwjgl={prop('1.20.1-fabric', 'deps.lwjgl')}</code>; the other Fabric nodes leave it blank. 1.21.1 Fabric and 1.20.1 Fabric set
`deps.gemrender_flywheel` (<code>{prop('1.21.1-fabric', 'deps.gemrender_flywheel')}</code> and <code>{prop('1.20.1-fabric', 'deps.gemrender_flywheel')}</code>): GemRender's 1.x Fabric jar nests Flywheel, which a Loom dev run does
not load, so the dev run adds it beside it. 26.1 NeoForge sets <code>deps.neoforge_floor={prop('26.1-neoforge', 'deps.neoforge_floor')}</code>, the oldest NeoForge the
released jar accepts (see [Scripting surface](../scripting-surface/#dev-runs)). JEI is optional: leave `deps.jei` blank to
build without it.

## The loader buildscripts

There is one buildscript per loader; Stonecutter runs it once per node of that loader. Each one:

1. sets the Java toolchain from `java_version` (26.1 on Java 25, 1.21.1 on 21, 1.20.1 on 17);
2. excludes the other loaders' `platform` packages from the main source set;
3. depends on Golem Core and HBM through Ivy repositories over their GitHub release downloads, and puts GemRender
   (CurseMaven, `curse.maven:<slug>-<project id>:<file id>`) and Sodium or Embeddium (Modrinth Maven,
   `maven.modrinth:<slug>:<version>`) in the dev client run. Golem Core is its release's `-dev` jar: the regular jar plus
   the harness listener, idle unless the harness launched the client (see [Testing](../testing/#scripted-client-checks));
4. fills the `${...}` placeholders in the metadata files and excludes the other loaders' metadata;
5. makes `compileJava` and `processResources` (and on NeoForge `createMinecraftArtifacts`) depend on
   `stonecutterGenerate`, or they read the previous node's source;
6. applies Golem Core's shared scripts from `gradle/golem/`.

Running a node on the wrong Java fails in confusing ways: a 1.21.1 NeoForge client on Java 25 dies with
`ClassNotFoundException: java.lang.Boolean`. `run-toolchain.gradle.kts` pins every run task to the node's Java.

GemRender is optional for players and only in the dev client run. Add `-Pgemrender.run=false` to launch without it, as a
player without GemRender would. Sodium (Embeddium on Forge 1.20.1) is in the dev client run for the same reason: many
players have it, and it renders chunks and block models its own way. Add `-Psodium.run=false` to launch on vanilla's
renderer.

### build.neoforge.gradle.kts

```kotlin title="build.neoforge.gradle.kts (trimmed)"
plugins {
    id("java-library")
    id("net.neoforged.moddev") version "2.0.141"
}

fun prop(name: String): String = property(name) as String
fun propOrNull(name: String): String? = (findProperty(name) as String?)?.takeIf { it.isNotBlank() }

val mcVersion = stonecutter.current.version
val javaVersion = prop("java_version").toInt()
val modId = prop("mod.id")

group = prop("mod.group")
version = "${prop("mod.version")}+$mcVersion"
base.archivesName = "$modId-neoforge"

java { toolchain.languageVersion = JavaLanguageVersion.of(javaVersion) }

sourceSets["main"].java {
    exclude("com/example/myaddon/platform/fabric/**", "com/example/myaddon/platform/forge/**")
}

val neoforgeFloor = propOrNull("deps.neoforge_floor") ?: prop("deps.neoforge")

neoForge {
    version = prop("deps.neoforge")
    runs {
        configureEach { systemProperty("neoforge.enabledGameTestNamespaces", modId) }
        register("client") { client(); gameDirectory = file("runs/client") }
        register("server") { server(); gameDirectory = file("runs/server") }
        register("gameTestServer") {
            type = "gameTestServer"
            gameDirectory = file("runs/gametest")
            systemProperty("golem.gametest.filter",
                providers.gradleProperty("gametest.filter").orElse("$modId:.*").get())
        }
    }
    mods { register(modId) { sourceSet(sourceSets["main"]) } }
}

repositories {
    mavenCentral()
    maven("https://maven.blamejared.com") { name = "BlameJared" }
    exclusiveContent {
        forRepository { maven("https://api.modrinth.com/maven") { name = "Modrinth" } }
        filter { includeGroup("maven.modrinth") }
    }
    exclusiveContent {
        forRepository { maven("https://cursemaven.com") { name = "CurseMaven" } }
        filter { includeGroup("curse.maven") }
    }
    // Golem Core and NTM - Continuum: the jars attached to their GitHub releases.
    for ((repo, group) in listOf("Golem-Core" to "github.golem-core", "NTM-Continuum" to "github.ntm-continuum")) {
        exclusiveContent {
            forRepository {
                ivy("https://github.com/Warfactory-Official/$repo/releases/download") {
                    name = repo
                    patternLayout {
                        artifact("v[revision]/[module]-[revision]+[classifier].[ext]")
                        // Releases up to 1.0.1 also carry the Minecraft version before the mod version.
                        artifact("v[revision]/[module]-[classifier]-[revision]+[classifier].[ext]")
                    }
                    metadataSources { artifact() }
                }
            }
            filter { includeGroup(group) }
        }
    }
}

// GemRender and Sodium carry mixins, so they go in the client run's mods folder: FML registers a classpath jar's code but not its
// mixin configs.
val devModJar: Configuration by configurations.creating

dependencies {
    // Golem Core's -dev jar: the regular jar plus the harness listener, idle unless the harness launched the client.
    implementation("github.golem-core:golemcore-neoforge:${prop("deps.golemcore")}:$mcVersion-dev")
    implementation("github.ntm-continuum:hbm-neoforge:${prop("deps.hbm")}:$mcVersion")
    if (propOrNull("gemrender.run") != "false") {
        propOrNull("deps.gemrender")?.let { devModJar("curse.maven:gemrender-1735539:$it") }
    }
    if (propOrNull("sodium.run") != "false") {
        propOrNull("deps.sodium_neoforge")?.let { devModJar("maven.modrinth:sodium:$it") }
    }
    compileOnly("org.jspecify:jspecify:1.0.0")
}

val syncDevMods = tasks.register<Sync>("syncDevMods") {
    from(devModJar)
    into(layout.projectDirectory.dir("runs/client/mods"))
}
tasks.matching { it.name == "runClient" || it.name == "prepareClientRun" }.configureEach { dependsOn(syncDevMods) }

val modProps = mapOf(
    "mod_id" to modId,
    "mod_name" to prop("mod.name"),
    "mod_version" to prop("mod.version"),
    "mod_author" to prop("mod.author"),
    "mod_license" to prop("mod.license"),
    "mod_description" to prop("mod.description"),
    "minecraft_range" to prop("deps.minecraft_range"),
    "neoforge_version" to neoforgeFloor,
    "neoforge_loader_range" to prop("deps.neoforge_loader_range"),
    "golemcore_floor" to prop("deps.golemcore_floor"),
    "hbm_floor" to prop("deps.hbm_floor"),
    "java_version" to javaVersion.toString(),
    "pack_format_entry" to if (mcVersion.substringBefore('.').toInt() >= 26)
        "\"min_format\": ${prop("pack_format")}, \"max_format\": ${prop("pack_format")}"
    else
        "\"pack_format\": ${prop("pack_format")}",
)

tasks.processResources {
    inputs.properties(modProps)
    filesMatching(listOf("META-INF/neoforge.mods.toml", "pack.mcmeta")) { expand(modProps) }
    exclude("fabric.mod.json", "META-INF/mods.toml", "data/$modId/forge/**")
}

tasks.named("createMinecraftArtifacts") { dependsOn(tasks.named("stonecutterGenerate")) }
tasks.compileJava { dependsOn(tasks.named("stonecutterGenerate")) }
tasks.processResources { dependsOn(tasks.named("stonecutterGenerate")) }

tasks.matching { it.name == "runGameTestServer" }.configureEach {
    doFirst { delete(layout.projectDirectory.dir("runs/gametest/world")) }
}

extra["mc_version"] = mcVersion
extra["java_version"] = javaVersion.toString()
extra["loader_cooking_result_count"] = true
apply(from = rootProject.file("gradle/golem/run-toolchain.gradle.kts"))
apply(from = rootProject.file("gradle/golem/harness-spec.gradle.kts"))
apply(from = rootProject.file("gradle/golem/legacy-recipes.gradle.kts"))
extra["loader"] = "neoforge"
apply(from = rootProject.file("gradle/golem/recipe-conditions.gradle.kts"))
apply(from = rootProject.file("gradle/golem/legacy-biomes.gradle.kts"))
apply(from = rootProject.file("gradle/golem/legacy-dimensions.gradle.kts"))
apply(from = rootProject.file("gradle/golem/legacy-assets.gradle.kts"))
// Dejson fails on an empty class list, so it is applied once gradle/dejson-classes.txt names a class.
if (rootProject.file("gradle/dejson-classes.txt").readLines().any { it.isNotBlank() && !it.trimStart().startsWith("#") }) {
    apply(from = rootProject.file("gradle/golem/dejson.gradle.kts"))
}
apply(from = rootProject.file("gradle/golem/mixin-validation.gradle.kts"))
apply(from = rootProject.file("gradle/golem/release-jar.gradle.kts"))
apply(from = rootProject.file("gradle/golem/mod-metadata.gradle.kts"))
apply(from = rootProject.file("gradle/golem/publish.gradle.kts"))
```

Golem Core and HBM go on the plain classpath: their own mixin configs are still applied there. The generated template
also adds JEI where the node sets `deps.jei_mc` and `deps.jei`. NTM: Space's file adds JEI
(`compileOnly` API jars, the full jar as a dev-only runtime mod), the dev-only probe addon's source set, KubeJS dev runs
(`-Pkubejs.run=true`) and the data generator (below).

### build.fabric.gradle.kts

Below 26.1 Fabric remaps mod dependencies, so they go in `modImplementation` and the build needs Mojang mappings. On 26.1
they are plain `implementation`.

```kotlin title="build.fabric.gradle.kts (trimmed)"

    id("java-library")
    id("dev.kikugie.loom-back-compat")
}

fun propOrNull(name: String): String? = (findProperty(name) as String?)?.takeIf { it.isNotBlank() }

val modId = prop("mod.id")

group = prop("mod.group")
version = "${prop("mod.version")}+$mcVersion"
base.archivesName = "$modId-fabric"

java { toolchain.languageVersion = JavaLanguageVersion.of(javaVersion) }

sourceSets["main"].java {
    exclude("com/example/myaddon/platform/neoforge/**", "com/example/myaddon/platform/forge/**")
}

repositories {
    mavenCentral()
    maven("https://maven.createmod.net") {
        name = "CreateMod"
        content { includeGroup("dev.engine-room.flywheel") }
    }
    exclusiveContent {
        forRepository { maven("https://api.modrinth.com/maven") { name = "Modrinth" } }
        filter { includeGroup("maven.modrinth") }
    }
    exclusiveContent {
        forRepository { maven("https://cursemaven.com") { name = "CurseMaven" } }
        filter { includeGroup("curse.maven") }
    }
    // plus the two GitHub release repositories, as on NeoForge
}

val obfuscated = mcVersion.substringBefore('.').toInt() < 26
val modCfg = if (obfuscated) "modImplementation" else "implementation"
val devRuntime = if (obfuscated) "modLocalRuntime" else "localRuntime"

// LWJGL pinned to what 1.20.1 ships
propOrNull("deps.lwjgl")?.let { pinned ->
    configurations.configureEach {
        resolutionStrategy.eachDependency { if (requested.group == "org.lwjgl") useVersion(pinned) }
    }
}

dependencies {
    "minecraft"("com.mojang:minecraft:${prop("deps.minecraft")}")
    if (obfuscated) "mappings"(loom.officialMojangMappings())
    modCfg("net.fabricmc:fabric-loader:${prop("deps.fabric_loader")}")
    modCfg("net.fabricmc.fabric-api:fabric-api:${prop("deps.fabric_api")}")
    // Golem Core (its -dev jar) and NTM - Continuum, as on NeoForge
    modCfg("github.golem-core:golemcore-fabric:${prop("deps.golemcore")}:$mcVersion-dev")
    modCfg("github.ntm-continuum:hbm-fabric:${prop("deps.hbm")}:$mcVersion")
    if (propOrNull("gemrender.run") != "false") {
        propOrNull("deps.gemrender")?.let { devRuntime("curse.maven:gemrender-1735539:$it") }
        propOrNull("deps.gemrender_flywheel")?.let { devRuntime("dev.engine-room.flywheel:flywheel-fabric-$mcVersion:$it") }
    }
    if (propOrNull("sodium.run") != "false") {
        propOrNull("deps.sodium_fabric")?.let { devRuntime("maven.modrinth:sodium:$it") }
        propOrNull("deps.indium")?.let { devRuntime("maven.modrinth:indium:$it") }
    }
    "compileOnly"("org.jspecify:jspecify:1.0.0")
}

loom {
    runs {
        named("client") { client(); runDir = "runs/client" }
        named("server") { server(); runDir = "runs/server" }
        register("gametest") {
            server()
            runDir = "runs/gametest"
            vmArg("-Dfabric-api.gametest")
            vmArg("-Dgolem.gametest.filter=${providers.gradleProperty("gametest.filter").orElse("$modId:.*").get()}")
        }
    }
}

val modProps = mapOf(
    "mod_id" to modId,
    "mod_name" to prop("mod.name"),
    "mod_version" to prop("mod.version"),
    "mod_author" to prop("mod.author"),
    "mod_license" to prop("mod.license"),
    "mod_description" to prop("mod.description").replace("\n", "\\n"),
    "minecraft_range" to prop("deps.minecraft_range"),
    "fabric_loader" to prop("deps.fabric_loader"),
    "golemcore_floor" to prop("deps.golemcore_floor"),
    "hbm_floor" to prop("deps.hbm_floor"),
    "java_version" to javaVersion.toString(),
    "pack_format_entry" to if (!obfuscated)
        "\"min_format\": ${prop("pack_format")}, \"max_format\": ${prop("pack_format")}"
    else
        "\"pack_format\": ${prop("pack_format")}",
)

tasks.processResources {
    inputs.properties(modProps)
    filesMatching(listOf("fabric.mod.json", "pack.mcmeta")) { expand(modProps) }
    exclude("META-INF/mods.toml", "META-INF/neoforge.mods.toml", "data/$modId/neoforge/**", "data/$modId/forge/**",
        "data/neoforge/**")
}

tasks.compileJava {
    dependsOn(tasks.named("stonecutterGenerate"))
    options.release = javaVersion
}
tasks.processResources { dependsOn(tasks.named("stonecutterGenerate")) }

tasks.matching { it.name == "runGametest" }.configureEach {
    doFirst { delete(layout.projectDirectory.dir("runs/gametest/world")) }
}

extra["mc_version"] = mcVersion
extra["java_version"] = javaVersion.toString()
apply(from = rootProject.file("gradle/golem/run-toolchain.gradle.kts"))
apply(from = rootProject.file("gradle/golem/legacy-recipes.gradle.kts"))
extra["loader"] = "fabric"
// then the same apply(...) lines as NeoForge, from recipe-conditions on
```

The Fabric file applies no `kubejs-order` script. `extra["mc_version"]` must be set on every loader: `legacy-recipes`
reads it, and Gradle configures every node's buildscript even when you build one.

### build.forge.gradle.kts

Forge 1.20.1 uses ModDevGradle's legacy Forge plugin. Its differences from the NeoForge file:

```kotlin title="build.forge.gradle.kts (differences)"
plugins {
    id("java-library")
    id("net.neoforged.moddev.legacyforge") version "2.0.141"
}

legacyForge {
    version = prop("deps.forge")
    runs {
        configureEach { systemProperty("forge.enabledGameTestNamespaces", modId) }
        // client, server, gameTestServer as on NeoForge
    }
    mods { register(modId) { sourceSet(sourceSets["main"]) } }
}

dependencies {
    // Golem Core (its -dev jar) and NTM - Continuum, as on NeoForge
    modImplementation("github.golem-core:golemcore-forge:${prop("deps.golemcore")}:$mcVersion-dev")
    modImplementation("github.ntm-continuum:hbm-forge:${prop("deps.hbm")}:$mcVersion")
    if (propOrNull("gemrender.run") != "false") {
        propOrNull("deps.gemrender")?.let { modRuntimeOnly("curse.maven:gemrender-1735539:$it") }
    }
    if (propOrNull("sodium.run") != "false") {
        propOrNull("deps.embeddium")?.let { modRuntimeOnly("maven.modrinth:embeddium:$it") }
    }
    compileOnly("org.jspecify:jspecify:1.0.0")
}

// modProps: "forge_loader_range" to prop("deps.forge_loader_range") instead of the NeoForge keys,
// and "pack_format_entry" to "\"pack_format\": ${prop("pack_format")}"
tasks.processResources {
    inputs.properties(modProps)
    filesMatching(listOf("META-INF/mods.toml", "pack.mcmeta")) { expand(modProps) }
    exclude("fabric.mod.json", "META-INF/neoforge.mods.toml", "data/$modId/neoforge/**", "data/neoforge/**")
}

extra["mc_version"] = mcVersion
extra["java_version"] = javaVersion.toString()
extra["convention_namespace"] = "forge"
// then the same apply(...) lines as NeoForge, with extra["loader"] = "forge"
```

The released Forge jars are reobfuscated, so `modImplementation` remaps them, as Loom does on Fabric below 26.1. There
is no `createMinecraftArtifacts` task and no `loader_cooking_result_count` on Forge. `convention_namespace` makes the shared
scripts use Forge 1.20.1's `forge:` convention tags in converted recipes and biome tags. NTM: Space's Forge GameTest run
also writes `level-type=minecraft:flat` into its `server.properties` before each run, so every run starts from an empty
flat world.

## The shared build scripts

Each loader buildscript applies Golem Core's scripts from `gradle/golem/`, after setting the `extra` values they read
(`mc_version`, `java_version`, `loader`). They are copies of `gradle/mod/` in Golem Core; keep them at the release
`deps.golemcore` names.

| Script | Does | Parameters (`golem.build.*`) |
|---|---|---|
| `run-toolchain` | pins run tasks to the node's Java | `runToolchain.clientFlags` |
| `harness-spec` | with `-Pharness.spec`, writes the client launch for the harness CLI instead of starting the game | none |
| `legacy-recipes` | rewrites recipe JSON for nodes below 1.21.2 | `legacyRecipes.componentSmeltingType`, `resourceTasks` |
| `recipe-conditions` | rewrites `"golem:conditions"` to the loader's spelling | `resourceTasks` |
| `legacy-biomes` | converts biome files for older nodes | none |
| `legacy-dimensions` | converts 26.1 dimension types for older nodes | none |
| `legacy-assets` | generates item models below 1.21.4 | `legacyAssets.modelNamespace`, `legacyAssets.selectProperties`, `legacyAssets.selfRenderedSpecialTypes` |
| `dejson` | writes declared models, blockstates, loot, tags and recipes; adds `dejsonVerify` and `dejsonOwnership` | `dejson.classes`, `dejson.authored`, `dejson.unownedFolders` |
| `generated-data` | packs data generated from Java (see [Recipes and data](../recipes-and-data/#build-wiring)) | `generatedData.generator`, `generatedData.root` |
| `mixin-validation` | fails `check` if a mixin config names a missing class | none |
| `release-jar` | writes the uploaded jar without GameTests to `build/release/` | `releaseJar.testPackages` (required), `releaseJar.testResources`, `releaseJar.testAssets` |
| `mod-metadata` | fills the `@golem.*@` links and credits in the metadata files | none (reads `mod.*`) |
| `publish` | uploads release jars to Modrinth and CurseForge (`publishAllMods`) | `publish.*` |
| `kubejs-order` (NeoForge, Forge) | orders your mod before KubeJS in the mod metadata, when the node sets `deps.kubejs` | none |

`dejson` fails when its class list names no class, which is why the buildscripts apply it only once
`gradle/dejson-classes.txt` names one. Apply `generated-data` only once your 26.1 NeoForge buildscript declares the
`runGenerateData` task it depends on (see [Recipes and data](../recipes-and-data/#build-wiring)); without it, the build
fails. Each script logs a count of what it converted. Read it after a change: a missing line means the script did
nothing.

## Mod metadata

Declare `golemcore` and `hbm` as required dependencies, from the floors in `gradle.properties`. On NeoForge and Forge
order your mod **after** both, so your start-up phases run after theirs.

```toml title="src/main/resources/META-INF/neoforge.mods.toml"
modLoader = "javafml"
loaderVersion = "${neoforge_loader_range}"
license = "${mod_license}"
issueTrackerURL = "@golem.issues@"

[[mods]]
modId = "${mod_id}"
version = "${mod_version}"
displayName = "${mod_name}"
displayURL = "@golem.homepage@"
authors = "${mod_author}"
description = '''${mod_description}@golem.credits@'''

[[dependencies.${mod_id}]]
modId = "neoforge"
type = "required"
versionRange = "[${neoforge_version},)"
ordering = "NONE"
side = "BOTH"

[[dependencies.${mod_id}]]
modId = "golemcore"
type = "required"
versionRange = "[${golemcore_floor},)"
ordering = "AFTER"
side = "BOTH"

[[dependencies.${mod_id}]]
modId = "hbm"
type = "required"
versionRange = "[${hbm_floor},)"
ordering = "AFTER"
side = "BOTH"

[[dependencies.${mod_id}]]
modId = "minecraft"
type = "required"
versionRange = "${minecraft_range}"
ordering = "NONE"
side = "BOTH"
```

`mod-metadata` replaces the `@golem.*@` tokens with `mod.homepage`, `mod.issues` and `mod.credits`. Leave out the
`issueTrackerURL` and `displayURL` lines while those properties are blank: an empty URL there is not a valid link.

Forge 1.20.1 reads `META-INF/mods.toml`: the same file with `loaderVersion = "${forge_loader_range}"`, a `forge`
dependency (`versionRange = "${forge_loader_range}"`) in place of `neoforge`, and `mandatory = true` in place of
`type = "required"` on every dependency. Keep `ordering = "AFTER"` on `golemcore` and `hbm`: Golem Core makes Forge's
parallel mod construction wait for them.

On Fabric, list your `ModEntry` under `golemcore:entry` (not `main`) and depend on both mods:

```json title="src/main/resources/fabric.mod.json"
{
  "schemaVersion": 1,
  "id": "${mod_id}",
  "version": "${mod_version}",
  "name": "${mod_name}",
  "description": "${mod_description}@golem.credits@",
  "authors": ["${mod_author}"],
  "license": "${mod_license}",
  "environment": "*",
  "entrypoints": {
    "golemcore:entry": ["com.example.myaddon.MyAddonEntry"]
  },
  "depends": {
    "fabricloader": ">=${fabric_loader}",
    "fabric-api": "*",
    "golemcore": ">=${golemcore_floor}",
    "hbm": ">=${hbm_floor}",
    "minecraft": "${minecraft_range}",
    "java": ">=${java_version}"
  }
}
```

With a homepage, add `"contact": {"homepage": "@golem.homepage@", "sources": "@golem.sources@", "issues": "@golem.issues@"}`.
Add a `client` entrypoint for client set-up. GameTests add a second `golemcore:entry` and, below 26.1, a
`fabric-gametest` entrypoint (see [Mod entry](../mod-entry/#fabric) and [Testing](../testing/#registering-per-loader)).

Every loader needs `pack.mcmeta`. The pack format key changed in 26.1 (`min_format`/`max_format` instead of
`pack_format`), so the buildscripts fill it in:

```json title="src/main/resources/pack.mcmeta"
{
    "pack": {
        "description": "${mod_name}",
        ${pack_format_entry}
    }
}
```

A wrong key here makes the game reject the whole pack: every recipe, tag and loot table of your mod silently disappears.

## Dejson lists

`gradle/dejson-classes.txt` names every class whose static fields or `declare()` method state models, loot, tags or
crafting recipes. `gradle/dejson-authored.txt` names hand-written JSON files that sit in folders Dejson owns. Both may
start empty (comments start with `#`). See
[Registering content](../registering-content/#dejson-what-to-declare-and-what-to-author).

## Package and namespace

- **Use your own Java package.** NeoForge loads mods as Java modules, and no package may be split between your jar and
  HBM's. Never put a class in `com.hbm.*`.
- **Use your own namespace** for everything you register and every data file you ship. Content ported from another mod
  keeps its path under your namespace (`ntmspace:moon_rock`). Never register into `hbm:`.
- To change HBM's own content, use [substitution](../substitution/), recipe removals, data map patches and fluid
  property patches, each in your own namespace.

## Building

You need a JDK (17 or newer) to start Gradle; the toolchain resolver downloads the Java each node needs.

```bash
./gradlew :26.1-neoforge:compileJava   # fastest check of the active node
./gradlew :26.1-neoforge:runClient
./gradlew chiseledBuild                # every node
./gradlew "Reset active project"       # back to the vcsVersion node before committing
```

Jars land in `versions/<node>/build/libs/` as `<mod id>-<loader>-<version>+<minecraft>.jar`; the copies without
GameTests, for uploading, in `versions/<node>/build/release/`. Stonecutter rewrites `src/` in place for the active node. Commit only with the
`vcsVersion` node active.
