# Continuum-Wiki

The wiki for making datapacks, KubeJS scripts and addon mods for
[NTM - Continuum](https://github.com/Warfactory-Official/NTM-Continuum). Built with
[Astro](https://astro.build) and [Starlight](https://starlight.astro.build), published to GitHub Pages at
https://warfactory-official.github.io/Continuum-Wiki/.

## Working on it

```bash
npm install
npm run dev      # http://localhost:4321/Continuum-Wiki/
npm run build    # static site in dist/
```

The site has one sidebar topic per audience: `getting-started`, `datapacks`, `kubejs` and `addons` under
`src/content/docs/`. Pages every audience needs (machine recipes, data maps, fluids and other data files, reference
tables) are written once in `src/shared/` and copied into each topic's `recipes/`, `data-maps/`, `data/` and
`reference/` folders by `scripts/shared-pages.mjs` on every build and dev start. Edit them in `src/shared/` only: the
copies are git-ignored and overwritten. Write links in a shared page as if it lived in the datapacks topic; links to
other shared pages are pointed at the same topic's copy.

Topic sidebars are configured in `astro.config.mjs`. Order pages in an autogenerated group with
`sidebar: { order: N }` in the frontmatter.

Every page has an "Open in AI chat" menu (`src/components/PageTitle.astro`) that asks a chat service to read the
page's Markdown copy; `scripts/markdown-pages.mjs` writes those copies and `llms.txt` after the build.

Internal links in page text must be relative (`../../recipes/overview/`), because the site is served under the
`/Continuum-Wiki/` base path. The landing page is the exception: its hero and card links are absolute
(`/Continuum-Wiki/...`), since it can be opened without a trailing slash, which breaks relative links.

Facts come from the mod's code. When a page and the code disagree, fix the page.

## Deploying

`.github/workflows/deploy.yml` builds and deploys on every push to `main`. In the repository settings, set
**Pages > Build and deployment > Source** to **GitHub Actions** once.
